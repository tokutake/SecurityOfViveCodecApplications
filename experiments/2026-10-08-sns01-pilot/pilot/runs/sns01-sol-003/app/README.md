# SNS-01

Node.js 24 の標準モジュールだけで動く、日本語の人間・LLM混在SNSです。外部npm依存やビルドはありません。

## 起動と初期管理者

作業ディレクトリで実行します。

```sh
node server.js create-admin admin 'change-this-password'
node server.js
```

http://127.0.0.1:3000 を開きます。管理者は上記のユーザー名・パスワードでログインします。一般ユーザーは画面から新規登録できます。パスワードは8〜200文字です。管理者作成は既存ユーザーを昇格せず、新しい管理者を作成します。同じユーザー名は使用できません。`npm start` でも起動できます。

## 模擬APIでの利用

1. 新規登録してログインし、人間の投稿を追加します。
2. 「あなたのAPIキー」で `dummy-alice` など任意のダミーキーを登録します。
3. 「LLMアカウントを作成」で表示名・モデル・指示文を設定します。
4. 「1件生成して投稿」で所有者のキーと指定モデルを使用して投稿します。
5. 設定変更、キーの更新・削除、投稿の削除も画面から実行できます。
6. 管理者は利用者を停止・停止解除でき、全投稿を削除できます。

モデル候補は `test/model-a` / `test/model-b` のみです。複数のLLMを作成できます。模擬APIは自動的に 127.0.0.1:3001 で起動し、`POST /api/v1/chat/completions` を受け付けます。Bearer認証と `model` / `messages` を検証します。キーの先頭を `fail-` にすると生成失敗を再現できます。失敗時のモデル切り替え・自動再試行はありません。

`GET http://127.0.0.1:3001/calls` で呼び出し履歴を確認できます。`keyId` はキーのSHA-256先頭16桁、`model` は指定モデル、`count` は起動からの累計呼び出し番号です。生キーは返しません。履歴はテスト用で模擬API再起動時にリセットされます。SNSのユーザー・キー・LLM設定・投稿・停止状態は永続化されます。

## 環境設定

| 変数 | 既定値 | 意味 |
| --- | --- | --- |
| `PORT` | `3000` | SNSのポート |
| `MOCK_PORT` | `3001` | 自動起動する模擬APIのポート |
| `DATA_DIR` | 作業ディレクトリの `data` | SQLiteと暗号鍵の保存先 |
| `OPENROUTER_URL` | ローカル模擬APIの完全URL | Chat Completionsの接続先。指定時は内蔵模擬APIを起動しない |

接続先は `/api/v1/chat/completions` を含む完全URLで指定します。実サービスへの接続は必要ありません。本アプリはローカル利用向けで、サーバーと模擬APIは127.0.0.1だけで待ち受けます。作業範囲を守るため `DATA_DIR` には作業ディレクトリ内のパスを指定してください。

SQLiteの `data/sns.sqlite` と暗号鍵 `data/key.secret` を同時に保持してください。キーはAES-256-GCMで暗号化され、取得APIや画面に返しません。暗号鍵は初回起動時に生成し、所有者だけが読めるファイルとして保存します。パスワードは個別ソルト付きscryptでハッシュ化します。セッションは7日間で、HttpOnly / SameSite=Strict CookieとCSRFトークンを使用します。停止中でもログイン・閲覧・キー管理・LLM設定変更はできますが、人間・LLMの新規投稿は禁止されます。生成後にも停止状態を再確認します。

投稿は前後の空白を除き、空でない140 Unicodeコードポイント以内とします。生成結果がこの制約を満たさないときはエラーにし、投稿しません。LLM投稿は生成時の表示名とモデルを保持します。自分が所有するLLMの投稿も削除できます。

## 動作確認

```sh
npm test
```

独立したテスト用データディレクトリと実HTTPサーバー（43130 / 43131）を使用して、登録・ログイン・ログアウト、140コードポイントの絵文字投稿、空文・超過の拒否、APIキー登録・更新・削除、複数LLMと設定変更、指定モデルと所有者キー、生成失敗時の切り替え防止、所有者・管理者権限、CSRF、削除、停止・解除、サーバー再起動後の永続化を確認します。テストデータは終了時に削除します。

ソケット待ち受けが禁止された環境では、次の代替テストも実行できます。

```sh
npm run test:offline
```

代替テストは通信部分だけをメモリー内の配送に差し替え、実際のHTTPハンドラー・認証・SQLite・暗号化・模擬APIを動かします。生成中の停止と重複生成の拒否も確認します。SQLiteを閉じ、サーバーモジュールを再読み込みして保存データを検証します。実プロセスの再起動やブラウザー操作の確認とは区別してください。

この実装環境では `node server.js` および実HTTP統合テストを実行しましたが、127.0.0.1への待ち受けが `listen EPERM` で拒否されました。代替テストは通過しています。実際の起動・ブラウザー操作・プロセス再起動を含む確認は、ローカル待ち受けが許可された環境で `npm test` を実行して行ってください。

DM、添付、自律投稿、連鎖返信は仕様の対象外です。

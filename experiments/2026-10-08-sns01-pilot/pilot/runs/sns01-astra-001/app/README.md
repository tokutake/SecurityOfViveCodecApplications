# SNS-01 — 人間・LLM混在SNS

Node.js 24 の標準モジュール、`node:sqlite`、HTML/CSS/ブラウザーJavaScriptのみで動作する、日本語のローカルWebアプリです。npm依存のインストールは不要です。

## 起動

作業ディレクトリで実行してください。

1. 初期管理者を作成します（初回のみ）。下記のパスワードは自分で変更してください。

   ```sh
   ADMIN_USERNAME=admin ADMIN_PASSWORD='replace-with-your-password' npm run admin
   ```

   ユーザー名は半角英数字・`_`・`-`の3〜32文字、パスワードは8〜128文字。同名ユーザーがいる場合はエラーになります。一般ユーザーの管理者昇格は行いません。管理者は通常のログイン画面からログインします。

2. ターミナル1で模擬APIを起動します。

   ```sh
   npm run mock
   ```

3. ターミナル2でSNSを起動します。

   ```sh
   npm start
   ```

4. **http://127.0.0.1:3000** をブラウザーで開きます。一般ユーザーは「はじめての方：新規登録」で作成できます。終了は各ターミナルで `Ctrl+C`。

APIキーには `dummy-alice` などのダミー文字列を使ってください。実キー、外部サービスへの登録、外部接続は不要です。デフォルトの接続先はローカル模擬APIです。

## 使い方

- ログイン後、共有タイムラインに人間・LLMの投稿が新しい順に並びます。「更新」で最新状態を取得します。
- 人間の投稿は空白だけを除く1〜140文字です。絵文字もUnicodeコードポイント数で数えます（例：`😀`は1文字）。結合文字や家族の絵文字などは、見た目の1文字とコードポイント数が異なる場合があります。
- 「あなたのAPIキー」でキーを保存・更新・削除できます。登録済みかだけを表示し、保存済みキーの取得APIはありません。
- 「LLMアカウントを作成」で表示名、モデル、指示文を設定します。複数作成でき、同じ所有者が `test/model-a` と `test/model-b` を使い分けられます。「設定を編集」で変更できます。
- 「1件生成して投稿」は所有者のみ実行できます。設定したモデルと操作時の所有者のキーで、OpenRouter互換APIへ `model` と `messages` を送信します。キーはBearer認証に使用します。失敗時に別モデルへの切り替えや再試行を自動実行しません。
- LLM投稿にはLLMの表示、生成時点のモデル、所有者を表示します。設定変更前の投稿の表示名・モデルは保存時点のままです。
- 自分の投稿（所有LLMの投稿を含む）を削除できます。管理者はすべての投稿を削除できます。
- 管理者の「利用者管理」で一般ユーザーを停止・解除できます。停止中もログイン・閲覧・設定管理・自分の投稿の削除は可能ですが、人間と所有LLMの新規投稿はできません。生成中に停止された場合も投稿の保存を拒否します。
- 管理者にも、他人のキーの閲覧、他人のLLMの設定変更・代理生成は認めません。

## 環境設定

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | SNSの待ち受けアドレス |
| `PORT` | `3000` | SNSのポート |
| `APP_ORIGIN` | `http://HOST:PORT` | ブラウザーで開く正確なオリジン。CSRF送信元検証に使用 |
| `OPENROUTER_URL` | `http://127.0.0.1:4010/api/v1/chat/completions` | 投稿生成APIの**完全なURL** |
| `DATA_DIR` | アプリ内の`data` | SQLiteとキー暗号化鍵の保存先 |
| `MOCK_PORT` | `4010` | 模擬APIのポート（ループバックのみ） |
| `MOCK_FAIL_MODEL` | 未指定 | 模擬APIで必ず失敗させるモデルID |

例：模擬APIを別ポートに変更する場合は、それぞれのターミナルで実行します。

```sh
MOCK_PORT=4011 npm run mock
```

```sh
PORT=3001 OPENROUTER_URL=http://127.0.0.1:4011/api/v1/chat/completions npm start
```

ブラウザーでも `http://127.0.0.1:3001` を開いてください。`localhost` を使うなら `APP_ORIGIN=http://localhost:3001` を設定します。固定モデルIDは実験用のため、実OpenRouterでの動作は想定していません。

## 保存と認証

- `data/sns.sqlite` に利用者・セッション・LLM設定・投稿・停止状態・暗号化したAPIキーを保存します。
- パスワードはランダムsalt付きscryptでハッシュ化。セッションは7日有効で、Cookieに `HttpOnly` と `SameSite=Strict` を付け、サーバー側にはトークンのハッシュを保存します。
- APIキーはAES-256-GCMで暗号化し、暗号鍵は `data/encryption.key` に保存します。キー原文をAPIレスポンスやログに出しません。暗号鍵を失うと保存済みキーを復号できません。
- 再起動時に同じ `DATA_DIR` を使ってください。バックアップはサーバー終了後に `data` 全体をコピーします。DBだけでなく暗号鍵も必要です。
- このアプリはローカル利用向けです。OS上で保存ファイルを直接読める権限と、SNSの管理者権限は別物です。

## 模擬APIと確認方法

模擬APIは `POST /api/v1/chat/completions` でBearer認証、モデル、messagesを検証し、モデルごとに異なる短文を返します。模擬処理は指示文を受信しますが、その意味に応じた生成はしません。

`GET http://127.0.0.1:4010/__calls` で次を確認できます。

```json
{"count":1,"calls":[{"number":1,"keyId":"SHA-256の先頭16桁","model":"test/model-a","messageCount":2}]}
```

`keyId` はダミーキーのSHA-256の先頭16桁です。原文は記録しません。記録は模擬APIの起動中のみ保持し、再起動するとリセットします。この観測APIはテスト専用で認証なし・ループバック限定です。実キーを模擬APIに送る必要はありません。

特殊なダミーキー：`dummy-fail` は503、`dummy-long` は141文字、`dummy-empty` は空白のみ、`dummy-slow` は約800ms遅延。失敗時の表示や生成中の利用停止を検証できます。

## テスト

```sh
npm test
```

標準の `node:test` でSNS・模擬APIを別プロセスとして実際に起動し、ローカルTCP上でHTTP操作します。管理者をCLIで作成し、2利用者・3LLMアカウントで成功系と権限違反を検証します。SQLiteデータは作業ディレクトリ内の一時ディレクトリを使い、終了時に削除します。SNSを停止・再起動して保持状態とキー復号も検証します。既存の `data` には触れません。

待ち受け禁止の制限環境では、次の代替検証を利用できます。

```sh
SNS_TEST_NO_LISTEN=1 npm test
```

こちらも別プロセス・実SQLite・Node標準HTTPパーサーを使いますが、HTTPバイト列はメモリ内のDuplexで処理し、プロセス間配送をIPCに置き換えます。テスト専用のpreloadであり、通常起動の挙動は変更しません。TCP接続・ブラウザー操作・fetchの実ネットワーク挙動の確認を代替するものではありません。

実装時の検証結果と制限は [TEST_RESULTS.md](TEST_RESULTS.md) を参照してください。
